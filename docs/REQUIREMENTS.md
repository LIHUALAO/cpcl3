## 零、一句话概括

**做一个能在当前网络环境下正常下载并启动 Minecraft 的启动器，要好用到接近甚至超过 PCL2。**

---

## 一、立项动机（最根本的要求）

### 原始表述

> 「因为目前 PCL2 被不可抗力影响不能再下载 MC 了，所以我准备重置一个。」
>
> 「内容应该是准备和他原本做的差不多。」

### 必须满足的

1. **绕开 PCL2 遇到的那类不可抗力** —— 不能把全部依赖压在单一第三方渠道上
2. **功能对标 PCL2** —— 玩家能从 PCL2 迁过来，不觉得少了什么
3. **能真正下载到 Minecraft**，不是「界面做好了但下不动」

### 技术上的实测结论（决定了架构）

立项时实测（2026-10，中国网络）：

| 端点 | 状态 |
|---|---|
| `launchermeta.mojang.com`（版本清单） | ✅ 直连可用 |
| `libraries.minecraft.net`（依赖库） | ✅ 直连可用 |
| `resources.download.minecraft.net`（资源） | ✅ 可用 |
| `cdn.modrinth.com`（Fastly） | ⚠️ **经常连不上** |
| `bmclapi2.bangbang93.com`（国内镜像） | ⚠️ 波动极大，会倒挂 |
| `authserver.mojang.com`（传统认证） | ❌ 已废弃 |

**结论**：卡住 PCL2 的不是「连不上」，而是**第三方渠道的单点依赖**。所以新项目必须：
- 元数据直连 Mojang
- 资源/库多源可选，**实测择优**
- 认证走微软 OAuth（唯一可行路径）

## 三、体验要求（比功能更重要）

这些不是功能清单，是主人反复表达的「感觉」。

### 3.1 好用程度对标 PCL2

> 「尽量让软件像 pcl2 一样好用」
>
> 「允许你增加和删除功能」

**这意味着**：不要拘泥于「照抄 PCL2 有什功能」，而是要**达到 PCL2 那种「点一下就能玩」的顺手程度**。

具体的差距清单见 `PCL2-GAP-ANALYSIS.md`，其中 PCL2 做得最好的三件事：

1. **启动前体检** —— 点启动前就告诉你「Java 不对 / 内存太小」，而不是等崩了
2. **崩溃后说人话** —— 「你的 XX mod 需要 Fabric API」，不是甩堆栈
3. **一次点击能做完** —— 点版本直接玩（缺 Java 自动装、缺库自动下）

### 3.2 中文优先

> 「默认中文界面 你官方源下载下来默认英文 不知道这个该怎么实现」

- 首次启动**必须是中文界面**
- 但要尊重用户后续手动改语言（不能强制改回来）

### 3.3 不要打扰用户

> 「又在打开文件夹 不要我醒了电脑都卡爆了」
>
> 「打开可以 让她记得关就行了」

- 测试/后台操作**不能弹窗打扰**
- 临时文件**必须清理**

### 3.4 界面信息要明确

> 「mod 下载列表这边我不知道下载给哪个版本了，选择太不明显了」

- 任何「装东西」的操作，**必须醒目显示目标**（装到哪个版本）
- 不能只放一个小下拉框让用户猜

## 四、对 AI 助手的构想（未来功能）

> 「我在思考有必要在里面内置一个你吗，emmm 接入网页版的？
> 然后给她这个软件的说明文件让她辅助操作？」

> 「最好本地吧，然后能对话能操作，比如我想玩机械动力2，
> 然后就执行下载整合包的操作，比如我装了一堆 mod 不知道什么 mod 冲突了，
> 把报错给他就能指出哪些问题，或者能直接检索可能冲突的 mod，
> 这样我们的 pcl 才是脱胎换骨的更加强大」

> 「或者不坐本地模型，我是想让所有下载客户端的人都能实现我们这个功能，
> 做成引入 api 或者调用反代一些网页免费的模型干活怎么样，反正非盈利」

> 「而且你可以写一个文件在里面放上想说给别的 ai 的东西……」

### 需求的三个场景

| 场景 | 用户输入 | 期望行为 |
|---|---|---|
| **装整合包** | 「我想玩机械动力2」 | 搜索 → 展示候选 → 确认 → 下载安装 |
| **查冲突** | 「装了 30 个 mod 冲突了」 | 分析依赖/版本/已知冲突 → 指出具体是哪个 |
| **看崩溃** | 贴一段崩溃日志 | 定位原因 → 给人话建议 |

### 接入方式（主人倾向）

1. **优先本地模型** —— 但主机器只有 4GB 显存（GTX 1660 Ti），只能跑 3B 级别
2. **其次自填 API Key** —— 稳定、便宜
3. **网页版反代** —— 主人明确表示可以做，但要标「随时失效」

### 关键技术现实（提供给 C# 实现者）

- DeepSeek 网页版有 **PoW（工作量证明）** 防护
  - `POST /api/v0/chat/create_pow_challenge` 取挑战
  - 本地用 **SHA3(wasm)** 暴力搜索 nonce 满足 difficulty
  - 再带 answer 调 `/api/v0/chat/completion`
  - **对方改版就会失效**，需持续跟进
- 网页版**不支持 function calling**，只能靠提示词约束输出结构化 JSON

### 我的建议（已写进 `AI-ASSISTANT.md`）

**先把「分析引擎」做扎实，模型只是外挂。**

因为主人提的三个场景里，前两个（搜整合包、查冲突）本质是**确定性逻辑**：
- 「机械动力」→「create」是固定映射（别名词典）
- mod 冲突 = 读 jar 元数据 + 比依赖 + 查冲突表

**这部分零成本、零幻觉、永远可靠**，比让模型猜准得多。

## 五、技术要求（如果要用 C# 重写）

### 5.1 为什么可以考虑 C#

主人问过：

> 「pcl2 是什么类型为什么那么小」

答：PCL2 是 **C# + WPF**，约 30 MB，因为 **.NET Framework 是 Windows 自带的**，不用打包运行时。

对比：

| 方案 | 体积 | 说明 |
|---|---|---|
| C# + WPF（PCL2 路线） | ~30 MB | 系统自带 .NET Framework |
| C# + .NET 8 + WebView2 | ~10 MB | 系统普遍预装 WebView2 |
| Electron | ~87 MB | 自带整个 Chromium |
| Node 便携版 | 30~50 MB | 自带 Node 运行时 |
| Tauri | 5~10 MB | 需 Rust 工具链 |

**如果重写用 C#，体积能对标 PCL2**，这是唯一的实质理由。

### 5.2 但要注意：这个项目的复杂度不在 UI

当前实现（TypeScript）的规模：

```
28,875 行源码 / 18,699 行测试 / 756 个测试用例
14 个 core 模块
```

其中**最值钱的是这几个模块的逻辑**，重写时别丢：

| 模块 | 行数 | 核心难点 |
|---|---|---|
| `launch/` | 2700 | rules 求值（最后一条匹配的 rule 生效）、17 个占位符、新旧参数格式、natives 解压、`clientJarVersion` 与 `realVersionId` 分离 |
| `download/` | 1987 | 三层失败防线（见 5.3）、断点续传、镜像回退、重定向跟随、SOCKS5 |
| `content/` | 4288 | Modrinth API、依赖解析、mrpack 解析、zip-slip 防护 |
| `auth/` | 1404 | 微软 OAuth 设备码 + XBL/XSTS/MC 三步换令牌 |
| `preflight/` | 1334 | 11 种检查、2ms 判定 |
| `java/` | 1173 | 按 component 精确匹配、多版本共存 |

### 5.3 重写时绝对不能丢的设计（血泪教训）

这些是花真金白银试出来的，换语言也要保留：

#### ① 下载失败的三层防线

**事故**：5147 个资产只落了 87 个，界面显示「安装成功」。

**根因**：并发池把 worker 异常收进 `errors[]` 不重抛，而调用方丢弃了返回值 → 任务凭空蒸发。

**必须保留**：
1. 接收并发池的 error 列表，异常任务计入 failed
2. **契约级不变量**：`skipped + downloaded + failed === total`，不等就抛错
3. **收尾磁盘复核**：逐个 stat 目标文件，全通过才发「完成」事件

#### ② 库合并必须区分 classifier

`com.mojang:jtracy:1.14.38` 和 `:natives-windows` 是**两个不同的库**。
只用 `group:artifact` 去重会导致后者覆盖前者，实测 121 个库掉到 63 个，启动时 `NoClassDefFoundError`。

#### ③ 加载器的 jar 归属

Fabric/Quilt 的版本 JSON 有 `inheritsFrom`，**但它自己没有 jar**。
classpath 最后一项必须用**祖先版本**的 jar。
所以要区分 `realVersionId`（= fabric-loader-xxx，用于版本名/natives 目录）和 `clientJarVersion`（= 26.3，用于拼 jar 路径）。

#### ④ Fabric profile 的 libraries 没有 downloads.artifact

它的 `libraries[]` 只有 `name` + `url`（+ 可选平铺 sha1/size）。
照原版逻辑套 `lib.downloads?.artifact` 会得到**空下载列表** → 表面装成功、依赖全缺、启动必崩。
必须三级回退：`downloads.artifact` → `url + mavenPath` → 裸下载。

#### ⑤ JVM 参数顺序

`-Duser.language=zh` 必须在 `-cp` **之前**。JVM 读到 `-cp` 就认为选项区结束。

#### ⑥ options.txt 只补不改

- 不存在 → 生成含 `lang:zh_cn`
- 有但没 `lang:` → **先备份再追加**
- 已有 `lang:` → **一个字都不写**（用户自己改过的语言要尊重）

#### ⑦ 打开文件夹的环回限制

`POST /folders/:kind/open` 会调 `explorer.exe`。必须：
- 只接受**环回地址**请求
- 拒绝代理转发（`X-Forwarded-For` 等）
- 路径 resolve 后必须仍在实例目录内

#### ⑧ 网络层的现实

- BMCLAPI 对 manifest 和 assets 都返回 **302**（不是 200）
- 按「200 才成功」写的逻辑在它会炸
- **不要假设国内镜像一定更快**，实测会倒挂

## 六、验收标准（主人怎么判断「做好了」）

按主人实际测试过的顺序：

### 必须能跑通的（缺一不可）

1. **装一个版本** → 资源文件数对得上（如 26.3 需要 5147 个 asset）
2. **点启动** → 游戏窗口真的弹出来
3. **界面是中文** → 「单人游戏」「多人游戏」
4. **能进单人游戏** → 创建世界正常
5. **装 Fabric** → 游戏里能看到模组列表
6. **装一个 mod** → 游戏里能看到它，没崩

### 主人踩过坑的地方（重点验证）

- 装完显示「成功」但启动崩 → **检查资产完整性**
- 界面显示正常但列表永远「正在加载」 → **检查前端 JS 是否加载**
- 布局错乱（面板堆在一起） → **检查 HTML 结构**
- 点某个按钮弹出一堆窗口 → **检查是否有测试残留**

## 七、给 C# 重写者的建议

- **不要照抄 `api.ts`** —— 5700 行的单文件是 web 架构的产物，C# 应该按模块分

### 7.3 强烈建议保留的

- **测试策略**：这个项目有 756 个测试，但真正抓到 bug 的是「真实副作用级」的那几个（真下载、真落盘、真 stat）
- **`scripts/check-hygiene.mjs` 的思路**：自动检查「调试残留」「临时目录堆积」
- **诚实报告失败**：这个项目的文档里写过「测试全绿但真实启动崩溃」，这种记录比炫耀成功有价值

### 7.4 不要做的事

1. **不要为了减小体积牺牲功能** —— 30 MB 和 10 MB 对玩家没区别，他们还要下 500 MB 游戏
2. **不要假设某个 CDN 一定可用** —— 一定要有测速和回退
3. **不要在测试里真弹窗、真留垃圾**
4. **不要为了「让它通过」而削弱下载校验** —— 那是用户装完游戏打不开的根源
